# Codex 0.150.0 alpha五天七连发：shell执行统一，装应用先验签

> 原文链接：[https://www.sz003.com/codexdt/2555](https://www.sz003.com/codexdt/2555)

<p>0.149 的正式版还停在那儿，试验田已经翻到了 0.150，这几天盯着 Codex 更新订阅源的人，观感多半如此。8 月 20 日到 22 日，七个 0.150.0 alpha 连着放出来（alpha.2 到 alpha.7），alpha.3 之后差不多一天一个，节奏快得像身后有人赶工期。alpha 别上生产，这是官方的原话。不过这一百多个提交翻下来，下一版的路线图已经能拼个大概。</p>
<figure><img decoding="async" src="https://cdn.laoshoucun.com/web/codex/2026/08/20260824223152_341876.png" alt="Codex 0.150.0 alpha 版本预览概念图" style="max-width:100%;height:auto"></figure>
<h2>这一批里最重的活：统一 shell 执行</h2>
<p>这批提交里，unified exec 这个标题出现了两回：一回主干合并，一回收尾清理。同一件事反复提交，我读出的信号是：一场不顺利、却绕不过去的架构迁移。旧 <strong><a href="https://www.sz003.com/" target="_blank" rel="noopener">Codex</a></strong> 里，shell 命令分好几条路径执行，行为细节各有各的毛病，排起问题来磨人。统一后，策略，审批，遥测全收进同一套管线，往后加新能力，不用每条路径再各补一遍。用户看不见这种重构，但开发者省了力，后面的功能才铺得开。</p>
<h2>先验签，再装应用</h2>
<p>安全线上也有值得盯的一条：Codex 应用在启动或安装之前，会先验证签名。听着像例行公事。前提摆在那儿，编程代理手里握着 shell 权限，桌面应用一旦被掉包，丢的就不只是数据。配套几条连着看：不信任的项目，project instructions 直接无视。macOS 上，偏好设置的读取被框进全盘策略。Seatbelt 的可写根路径绑定也同步加固。</p>
<p>线索拼到一块儿，0.150 的主题浮出来了：执行入口收紧，信任边界画明白。天天把代码和权限往外交的人，看到这个方向，比看到两个新功能更踏实。</p>
<h2>小改进，个个踩在痛点上</h2>
<p>小活也挑得准。TUI 状态栏可以配着显示主机名，远程连多台机器的人，不用再猜命令敲在了哪台上。token 预算受限的会话，添了 history 和 notes 两个工具，长对话不必光靠压缩硬扛。自定义模型 provider 能上报每轮成本遥测，走第三方网关的用户总算能把账算清。Amazon Bedrock 那头，多代理编排切到 V1 模式，压缩改走 Responses 接口，企业用户的体验一点点对齐过来。</p>
<h2>alpha 碰不碰</h2>
<p>我的意见：再等等。unified exec 的迁移走到半路，日常重度使用撞见边缘问题的概率不低，等 0.150.0 正式版落了地再动手，更稳。手痒想尝鲜，就装个隔离环境随便玩。<a href="https://www.sz003.com/" target="_blank" rel="noopener">官网</a>的更新说明和站内<a href="https://www.sz003.com/jiaocheng" target="_blank" rel="noopener">教程</a>，会在正式版出来后跟上。多数人把 0.149.0 用明白，比追着 alpha 跑实在，下个大版本往哪走，心里有数就够了。</p>
