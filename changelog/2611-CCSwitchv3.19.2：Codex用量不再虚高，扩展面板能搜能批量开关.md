# CC Switch v3.19.2：Codex 用量不再虚高，扩展面板能搜能批量开关

> 原文链接：[https://www.sz003.com/ccswitchdt/2611](https://www.sz003.com/ccswitchdt/2611)

<p>跑 <a href="https://www.sz003.com/ccswitchdt" target="_blank" rel="noopener">CC Switch</a> 的人大多盯过它的用量看板，限额还剩多少、这个月烧了多少，数字对不对直接关系心里有没有底。8 月 6 日的 v3.19.2 就是冲这个来的，<a href="https://www.sz003.com/" target="_blank" rel="noopener">Codex</a> 用量统计有个藏得挺深的缺陷，会把真实消耗多算好几倍。</p>
<figure><img decoding="async" src="https://cdn.laoshoucun.com/web/codex/2026/09/20260903115540_461367.png" alt="CC Switch v3.19.2 版本更新概念图" style="max-width:100%;height:auto"></figure>
<p>修复本身拿近 1900 份真实会话文件回放验证过，和独立重算的理想值偏差只有 0.001%，这个验证规模在修复型版本里算少见。</p>
<h2>数字为什么会虚高</h2>
<p>缺陷出在交错计数器文件上。真实日志里存在这样的文件，同一份快照被网关换着限额桶反复重播，或者两个累计计数器交替出现，旧算法会把它们当成新增量，现场文件实测虚高 6 到 8 倍。也就是说看板上那个吓人的数字，可能一半是重复算的。历史数据不会自动改写，需要的话去用量页手动重建一次，升级后的新数据从那一刻起就是对的。</p>
<h2>面板能搜了，开关能批量了</h2>
<p>MCP、提示词和 Skills 三个面板都加了搜索框。MCP 和 Skills 列表上的应用徽章变成三态开关，点一下就能把某个应用在整张列表上批量启用或停用，不用再一条条翻。两个边界问题也顺手修了，新版 Claude Code 对不认识的 API key 会弹默认 No 的确认框，现在改写占位符直接进会话，不再看到未登录的界面；OMO 4.19.3 改了配置文件位置，检测到统一文件就往对的分区写，切换不再落空。</p>
<h2>六项加固加一次提速</h2>
<p>这一版没有数据库迁移，安全侧做了一轮六项加固，把用量脚本、会话日志和目录文件的无界读取全部封顶。代理缓冲响应体同样套了边界，输入再大也吃不住内存。两条写盘路径改成批量处理，备份导出用批量 INSERT，同步恢复走单事务，Codex 用量全量重导入在真实语料上从 36.3 秒降到 11.1 秒。还补了个诊断能力，第三方网关吞掉工具调用时不再静默当本轮完成，而是明确报错并留结构化日志，Codex 无声结束循环这类问题终于能从真实流量里查了。</p>
<h2>要不要升</h2>
<p>用量看板用户这版是实打实的正收益，数字先对起来心里才有底。历史虚高记得手动重建一次，入口在用量页。安全加固这类改动平时看不见，出事才知道值钱，建议照常升级。</p>
